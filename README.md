# Shorts Lab — YouTube Shorts 連続再生・品質調査

HTML / CSS / JavaScript と YouTube IFrame Player API だけで動作する日本語の静的Webツールです。アプリ用のサーバー、APIキー、npm依存パッケージ、ビルドは不要です。

## 使い方

1. HTTPでサイトを開き、調査対象のURLを追加します。Shorts、watch?v=、youtu.be形式に対応します。
2. 切替間隔（整数5〜120秒、初期値20秒）を設定して「計測開始」を押します。ミュートが初期設定です。
3. 切替処理の開始から設定秒数後、または動画終了時に次へ進みます。末尾から先頭に戻ります。再生開始の遅れや手動一時停止でも期限は延長しません。間隔変更は次の切替から適用します。
4. 「計測終了」で再生・切替・監視を停止します。「CSVをダウンロード」でUTF-8 BOM付きCSVを取得します。計測中の出力も可能です。

動画リストはブラウザのlocalStorageに保存されます。計測中は編集できません。ログはメモリ上で保持し、画面には直近500件、CSVには全件を出力します。再計測・ページ再読み込みで前回ログは消えるため、先にCSVを保存してください。

## ローカル開発

Node.js 24、Python 3を使用します。既存チェックアウトで実行してください。

```sh
cd /workspace/youtubeshort-check
npm test
npm run serve
```

任意の静的HTTPサーバーでも動作します。ES ModulesとYouTubeの埋め込み識別情報のため、HTMLファイルをfile://で直接開かないでください。

## GitHub Pages

1. この変更をGitHubの`main`へ反映します。
2. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に設定します。
3. `.github/workflows/pages.yml` がテスト後、必要な静的ファイル4個をデプロイします。必要ならActionsから手動実行できます。
4. 公開URLをPC Chromeで開き、埋め込みを許可した実動画を登録して再生・CSV出力を確認してください。

サブディレクトリ公開に対応する相対パスを使用しています。公開先の操作・実際のデプロイは本実装のローカル検証では行っていません。

## 計測の定義

- **状態**：UNSTARTED / PLAYING / PAUSED / BUFFERING / ENDED / CUED をonStateChangeで記録。
- **バッファリング**：BUFFERINGへの遷移を1回とし、次の状態または切替・終了までの実時間を集計。
- **停滞疑い**：500ms間隔でgetCurrentTime()を確認。PLAYINGになった後、再生位置が2秒以上進まない場合に1回記録。進行再開・状態変更・切替・終了で閉じます。継続時間は検出前の2秒も含みます。切替待ち・手動一時停止・終了前1秒・シークは除外します。
- **累計停止時間**：バッファリング時間＋停滞疑い時間。両者は重複集計しません。手動一時停止を含めません。
- **再生開始まで**：各切替処理開始から最初のPLAYINGイベントまで。
- **実再生時間**：PLAYING中の再生位置の増分を、サンプル間の実時間を上限に集計。大きなシークを除外した推定値で、切替ごとの「動画別計測結果」の継続時間に出力。同じ動画の再訪は別行です。
- **経過時間**：計測開始から終了までの単調増加時計による実時間。

CSVの日時はISO 8601 UTC、画面の日時は閲覧端末のローカル時刻です。継続時間の意味はイベントによって異なります（再生開始は待ち時間、停止終了は停止時間、動画別計測結果は実再生時間）。

映像フレーム自体の停止を直接検出するものではありません。ブラウザのバックグラウンド化、広告、ネットワーク、APIの観測精度、再生速度、シークにより値が変動します。バックグラウンドでは警告し、停滞判定を抑制します。復帰時、切替期限超過なら次へ進みます。ブラウザのタイマー制限下では厳密な秒数は保証できません。

自動再生ブロック、5秒間の再生開始待ち、API読込失敗、再生エラーは画面に通知します。再生エラーは記録後、設定済み期限で次へ進みます。広告・年齢制限・埋め込み制限などを回避しません。

## 検証結果

- `npm test`：10件成功。URL解析、20秒期限（再生遅延を含む）、循環、終了時切替、間隔変更、バッファリング、停滞と除外条件、実再生時間、停止、CSVを検証。
- ChromiumのUI統合テスト：成功。YouTube APIの**テストダブル**を使い、URL追加・削除・保存、開始、バッファリング・停滞表示、終了イベント、5秒切替と循環、位置リセット、計測終了、CSVダウンロードとBOM、390px表示、JavaScriptエラーなしを確認。
- 実YouTube再生・実動画の20秒切替・公開済みGitHub Pagesでの動作：**未確認**。クラウドのネットワークポリシーによりYouTube接続が403で拒否されました。参考サイトもアクセス拒否のため閲覧できていません。

任意のUIテストは、別途PlaywrightとChromiumを利用できる環境でHTTPサーバーを起動して実行します。通常のサイト動作や単体テストには不要です。

```sh
PLAYWRIGHT_MODULE=/absolute/path/to/playwright CHROME_PATH=/usr/bin/chromium node tests/browser-check.cjs
```

クラウド環境の設定ドラフトには起動手順とYouTube用の許可ドメイン（`www.youtube.com`, `*.youtube.com`, `*.googlevideo.com`, `*.ytimg.com`）を保存しています。ドラフト保存だけでは現在の通信制限は変わりません。環境設定で確認・保存し、環境を公開した後、実動画で再検証が必要です。

## Pages公開で「Get Pages site failed / Not Found」になる場合

このツールはHTMLをそのまま公開するため、`actions/configure-pages`のメタデータやビルド設定を使用しません。ワークフローはテスト → 静的ファイル作成 → artifactアップロード → deploy-pagesで公開します。必要な`contents: read`、`pages: write`、`id-token: write`は設定済みです。

`configure-pages@v5`の`enablement: true`は、通常の`GITHUB_TOKEN`だけではPagesサイト作成を保証できません。公式仕様では別の適切な権限付きトークンが必要なため、本ツールでは追加の秘密情報を要求せず、不要なconfigure-pages手順を省いています。Pagesサイトの有効化自体はGitHubのSettings → Pagesで行ってください。

デプロイ段階でもNot Foundとなる場合は、リポジトリ管理者としてPagesのSourceがGitHub Actionsになっているか、非公開リポジトリの場合は契約プランがPagesを利用できるか、組織のPages制限がないか確認してください。configure-pagesの省略だけで未作成のPagesサイトが作成されるわけではありません。
